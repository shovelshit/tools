# Maoyan Orbit 共享前端设计

## 背景

猫眼监控工具已经同时运行在 Web 与 Electron 中，并由 `pages/maoyan` 提供唯一一套共享业务页面。现有页面功能完整，但信息按普通表单和卡片堆叠，连接、监控、通知、锁座等操作的优先级不够明确，也没有形成适合常驻桌面的视觉语言。

本次采用 IBM Carbon Design System 作为组件尺寸、交互状态和无障碍规范的基础，在其上建立独立的 `Maoyan Orbit` 主题。主题表现为克制的星舰控制台：深色中性表面、青色导航与实时状态、猫眼红主操作、琥珀告警，以及少量等宽遥测数据。

## 目标

- Web 与 Electron 继续共享 `pages/maoyan`，不产生平台专属业务页面。
- 将首次连接到启动监控整理成明确的四步流程。
- 在常驻桌面窗口中快速识别 Worker、监控、登录态与锁座状态。
- 让普通用户可以只阅读中文完成任务，高级信息不阻塞主流程。
- 建立可在 Figma 和代码中一一对应的组件、变量及状态体系。
- 保持现有 Worker API、D1/KV 数据和锁座协议不变。

## 非目标

- 不迁移到 React、Vue 或其他前端框架。
- 不在本次调整 Worker 调度、监控频率或容量架构。
- 不重新设计猫眼官方座位图内容，只调整其外层容器和控制区。
- 不为科技感加入 WebGL、3D 场景、持续粒子动画或背景视频。
- 不通过 CDN 加载 Carbon 运行时代码、字体或其他第三方资源。

## 设计原则

1. 科幻感来自状态和结构，而不是装饰。坐标、扫描周期、阶段编号和链路状态必须对应真实数据。
2. 正常状态保持安静。红色只用于主操作和错误，战术红框只在锁座倒计时、登录失效或任务失败时出现。
3. 中文是主要信息。英文遥测标签只作为辅助层，不替代按钮、错误提示和关键字段。
4. 同一状态只使用一个强调色，并同时提供图标或文本，不能只依赖颜色表达。
5. 所有核心操作在 1024 x 720 桌面窗口和 390 x 844 移动视口中都可完成。

## 产品结构

### 登录与连接

首次进入显示独立连接界面，而不是营销页。内容包括产品名、Worker 地址、访问令牌、安全提示和连接按钮。

- Electron 可读取已保存的 Worker profile，并明确标出凭据是否来自系统安全存储。
- Web 不显示 Electron 专属能力。
- HTTP Worker 使用琥珀安全提示，非本机 HTTP 仍保留当前阻断式确认。
- 连接中、成功、认证失败、网络失败分别使用独立状态文案。

### 四步配置

主流程固定为：

1. 连接服务
2. 选择影院
3. 选择影片
4. 通知与启动

桌面端使用左侧阶段轨道。完成步骤显示绿色校验状态，当前步骤显示青色舱段，高风险错误显示红色状态但不改变步骤顺序。用户可返回已完成步骤修改配置，未满足依赖的后续步骤不可进入，并显示具体缺失条件。

移动端将阶段轨道压缩为顶部四段进度条，只显示当前步骤标题和 `n / 4`，主操作固定在底部安全区域上方。

### 运行监控

监控启动后，页面从配置态切换为运行态：

- 顶部遥测条显示 Worker 在线状态、最近同步时间、监控时段和下次检查倒计时。
- 主区域显示影院、影片目标、最近检查结果和变化记录。
- 停止监控是次级危险操作，需要确认，但不能与启动按钮使用相同视觉权重。
- 页面可见时保持现有实时刷新感；页面隐藏时的轮询优化属于独立后端容量任务，不在本设计中改变。

### 锁座

锁座入口位于运行态的目标区域，不与常规设置混排。弹窗分为四个稳定区域：

- 猫眼会话：Electron 登录、Web 不支持说明、手动上传登录态、会话状态。
- 场次规则：目标日期、模板场次、同厅型与 `+30 分钟` 偏差说明。
- 座位目标：官方座位图、选择结果与只读对比。
- 执行状态：等待场次、尝试锁座、成功、失败及通知结果。

只有进入实际锁座尝试或严重异常时启用战术告警模式。普通规则配置沿用星舰控制台主题。

## 响应式布局

### 1280 px 及以上

- 顶部遥测条 24 px，应用栏 56 px。
- 左侧阶段轨道 208 px。
- 中央工作区使用剩余宽度，最小 620 px。
- 右侧诊断区 248 px，展示下次检查、目标数量和链路状态。

### 1024-1279 px

- 隐藏右侧诊断区，其关键信息合并到中央页头。
- 左侧阶段轨道缩至 176 px。
- 主操作保持右下固定位置，不因状态文字变化发生位移。

### 767 px 及以下

- 改为单列布局，阶段轨道替换为顶部进度条。
- 遥测条只保留在线状态和下次检查。
- 表单标签置于输入框上方，选项采用全宽分段控制。
- 底部操作区固定高度，并适配系统安全区域。
- 锁座座位图允许横向平移和缩放，工具按钮不覆盖座位。

## 视觉系统

### 颜色变量

| Token | 值 | 用途 |
|---|---|---|
| `orbit-bg` | `#071015` | 页面背景 |
| `orbit-layer-01` | `#0B171D` | 应用栏与侧轨 |
| `orbit-layer-02` | `#0D1B21` | 主工作区 |
| `orbit-layer-03` | `#12252C` | 选中表面与字段组 |
| `orbit-border` | `#27454E` | 默认边界 |
| `orbit-focus` | `#42E1E5` | 焦点、当前步骤和实时状态 |
| `orbit-action` | `#F04B52` | 主操作与错误 |
| `orbit-success` | `#62D99A` | 已完成和连接成功 |
| `orbit-warning` | `#E7B64E` | 风险提示与等待 |
| `orbit-text-primary` | `#E9F8F8` | 主文本 |
| `orbit-text-secondary` | `#8BA1A8` | 辅助文本 |

Figma 变量按 `Primitive / Semantic / Component` 三层组织。代码中只允许组件引用语义变量，不直接引用基础色值。

### 字体

- 中文与正文：Figma 使用 Inter + 思源黑体，代码使用系统无衬线字体栈，避免在线字体依赖。
- 数字、时间和状态码：`SFMono-Regular, Consolas, Liberation Mono, monospace`。
- 正文最小 12 px，辅助遥测最小 10 px；移动端不缩小字体换取布局。
- 字间距固定为 `0`，不使用负字距。

### 形状与装饰

- 表单和普通按钮圆角 2-4 px，弹窗最大 6 px。
- 当前面板可使用一组静态 HUD 角标，但不能包围所有内容。
- 扫描线只允许作为低对比静态纹理，默认透明度不超过 3%。
- 不使用光球、霓虹渐变、玻璃拟态或无业务含义的雷达动画。

## Figma 组件库

Figma 文件包含以下页面：

1. `00 Foundations`：颜色、排版、间距、阴影、图标与栅格。
2. `01 Components`：基础组件及其变体。
3. `02 Desktop`：连接、四步配置、运行监控和锁座。
4. `03 Mobile Web`：移动连接、配置、监控和锁座。
5. `04 States`：加载、空、成功、等待、失效、失败和离线。
6. `05 Prototype`：首次连接到启动监控，以及锁座规则到执行结果的点击流程。

首批组件：

- `Button`：primary、secondary、ghost、danger、loading、disabled。
- `IconButton`：default、hover、focus、disabled，并提供 tooltip。
- `TextInput`：default、focus、filled、error、disabled、password。
- `Select / Combobox`：default、open、loading、empty、error。
- `SegmentedControl`：通知渠道和模式切换。
- `StatusBadge`：online、offline、waiting、success、warning、error。
- `StepRail / StepProgress`：desktop 与 mobile 两种布局。
- `TelemetryItem`：label、value、timestamp、countdown。
- `Notification`：inline 与 toast，按信息级别区分。
- `Dialog / Drawer`：普通配置与锁座两种尺寸。
- `ActionBar`：back、autosave state、primary action。

Carbon 组件用于对齐交互状态、尺寸与可访问性，不直接复刻 IBM 配色、产品栏和品牌图形。

## 代码实现边界

现有页面没有共享前端构建流程，Electron 直接打包 `pages/maoyan` 中的静态文件。因此首阶段不整体替换成 Carbon Web Components，也不从 CDN 加载运行时代码。

实施方式为：

1. 将 Figma 语义变量映射为 `pages/maoyan` CSS custom properties。
2. 保留现有语义化 `button`、`input`、`dialog` 和业务元素 ID，降低 `app.js`、`lock.js` 回归风险。
3. 把重复样式提取为小型共享组件类，并按 Carbon 状态规范补齐 hover、focus、disabled、loading 和 error。
4. 仅在原生控件无法可靠满足无障碍交互时，引入选定的 Carbon Web Component；依赖必须本地打包并同时进入 Web 与 Electron 产物。
5. 使用本地 SVG 图标资源，不使用 emoji 充当正式操作图标。

这样保留 Carbon 设计系统的价值，同时避免为了视觉重构引入 React 或远程运行时依赖。

## 数据与交互

本次不改变 API 请求和保存语义。视觉组件只消费现有页面状态：

- Worker 连接状态来自当前 runtime 与 `/api/status`。
- 配置步骤完成度由现有 Worker profile、影院、影片与通知配置计算。
- 自动保存状态由真实请求生命周期驱动，不模拟成功。
- 监控和锁座倒计时使用已有 cron、规则和执行状态。
- Web/Electron 差异继续由 `runtimeInfo` 控制，不复制页面模板。

加载超过 300 ms 才显示进度；提交类操作禁止重复触发。错误提示保留在相关字段或操作附近，同时写入现有记录区。任何错误文本都不得包含 Token、Cookie、`mtgsig` 或完整登录态。

## 可访问性

- 文字与背景达到 WCAG AA 对比度。
- 所有交互元素具有明确的键盘焦点，焦点环至少 2 px。
- 阶段、成功、警告和错误同时使用图标、文字与颜色。
- 支持键盘完成连接、影院选择、影片选择、通知配置和弹窗关闭。
- 尊重 `prefers-reduced-motion`，关闭扫描移动、脉冲和数字滚动动画。
- tooltip 不承载完成任务所必需的信息。
- 座位图外围控制提供可访问名称，官方座位图本体维持现有只读语义。

## 验证策略

### 视觉回归

- 使用 Playwright 截图比较 1440 x 900、1024 x 720、768 x 1024 和 390 x 844。
- 覆盖 Web 与 Electron 共享页面的连接、四个步骤、运行态和锁座弹窗。
- 检查长影院名、长错误信息和最大数量状态下没有溢出或遮挡。

### 交互回归

- 保留现有 DOM ID 与主要事件路径，运行 Worker 和 Electron 现有测试。
- 增加四步完成度、返回修改、提交防重和运行态切换的浏览器测试。
- 验证 Web 登录按钮仍明确不可用，Electron 登录与手动上传仍可用。
- 验证主题重构不改变 Worker URL、Token、配置和锁座请求内容。

### 无障碍验证

- 对连接页、配置页和锁座弹窗运行自动化可访问性扫描。
- 手工验证键盘顺序、焦点陷阱、Esc 关闭、错误定位和降低动态效果。
- 在浅色系统和深色系统环境中确认控件颜色不被平台默认样式覆盖。

## 交付顺序

1. 在 Figma 建立 Foundations 和组件变体。
2. 完成桌面四步配置与运行态高保真稿。
3. 完成锁座弹窗和战术告警状态。
4. 完成移动端适配与交互原型。
5. 用户确认 Figma 后，再制定代码实施计划。

## 验收标准

- Figma 中所有页面使用共享变量和组件实例，不存在重复手绘控件。
- 桌面和移动端均能完整走通首次连接、四步配置和启动监控。
- 正常界面采用星舰控制台，严重异常才采用战术红色告警态。
- 关键状态均来自真实业务数据，不使用装饰性假指标。
- Web 与 Electron 仍共享一套页面和交互逻辑。
- 页面不依赖第三方 CDN，敏感数据处理方式不变。
- 现有监控、通知、登录态上传、座位选择和锁座流程无行为回归。
