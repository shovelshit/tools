# VitePress 项目使用教程站设计

## 目标与范围

在 `guide.ltools.asia` 新增独立的 VitePress 静态教程站，让访客按项目找到可执行的使用说明。教程首页保持简洁，只列项目入口；文章以准备条件、操作步骤、结果验证和常见问题为主，不做按时间排序的博客流。

首批覆盖 README 中的四个项目：电影场次监控与自动锁座、应用商店、领克签到助手、蓝牙调试助手。每个项目先提供一篇入门教程。后两个项目属于独立仓库，写作时以其当前 README 和发布说明核对安装、权限及操作步骤；无法从当前资料确认的细节只链接上游说明，不编造流程。

本次实现站点、教程内容、工具箱首页重构和独立构建配置，不创建线上 Cloudflare Pages 项目、绑定 DNS 或部署生产环境。不引入评论、账号、CMS、标签、搜索或文章时间线。

## 页面与内容

- `https://guide.ltools.asia/`：站点标题、简短说明和四个项目的单列入口；顶部提供返回工具箱首页的链接。
- 每篇教程：标题、适用场景、准备条件、分步操作、如何验证成功、常见问题与相关链接。使用 VitePress 默认的文章目录和移动端导航，少量样式调整即可，不重建主题组件。
- 猫眼教程：以访问密钥、城市/影院/影片关注、测试推送和监控状态为主；自动锁座作为可选章节，清楚区分会话准备、规则保存和实际下单，不要求读者在教程中执行真实订单。
- 应用商店教程：浏览资源、预览和下载，并说明无需登录的访问方式。
- 领克和蓝牙教程：分别覆盖上游项目确认过的最短可用流程；示例不包含会话、令牌、推送密钥或其他真实凭据。

教程站内链接使用站点根路径；打开真实工具或外部仓库时使用明确的外链。`pages/index.html` 重构为简单的工具目录：保留四个现有工具入口及其目标地址，增加醒目的“使用教程”入口，移除大面积渐变头图和冗余装饰，视觉与教程站保持一致；不改四个工具的业务页面。

## 构建与集成

教程 Markdown、VitePress 配置、轻量样式及独立锁文件放在仓库根目录的 `guide/`。站点以 `/` 为 base，本地用 `npm --prefix guide ci` 和 `npm --prefix guide run build` 构建，产物留在 `guide/.vitepress/dist/`，不写入 Worker 的 `public/`。忽略生成产物和 `node_modules`，不把本地文档或凭据打包进去。

生产目标为独立的 Cloudflare Pages 站点：构建根目录是 `guide/`，构建命令为 `npm run build`，输出目录是 `.vitepress/dist/`，自定义域名为 `guide.ltools.asia`。仓库提供发布配置说明；实际 Pages 项目和 DNS 状态须在发布时确认。Worker 的构建脚本、Wrangler 路由、API、静态资源策略和调度逻辑都不变。

`pages/index.html` 是工具箱首页源码，但不在当前 Worker 静态资源白名单中；修改它只能保证仓库源码有入口，不能推断根站点已随 Worker 部署更新。上线时须另行确认根站点发布路径，并分别检查首页与教程站的双向链接。

## 验证与边界

- 安装锁定依赖后，独立 VitePress 构建可重复运行；产物包含首页、四篇教程和所需脚本/样式，并且不进入 Worker 发布目录。
- 检查教程首页、各文章、未知路径 404、四个项目到工具或上游仓库的链接，以及工具箱首页到教程站的入口；产物不得包含忽略的本地资料或密钥。
- 测试工具箱首页原有四个链接不变；在桌面与手机视口检查两站的导航、正文、代码块和长链接无溢出。Worker 未修改，现有测试可作为回归基线运行。
- 教程内容只以当前代码和上游资料为依据；外部应用权限、根站点的发布路径、Pages 项目/DNS 配置和生产域名可达性仍需发布时单独核对。
