# VitePress 项目使用教程站设计

## 目标与范围

在现有工具箱旁新增 `/guide/` 静态教程站，让访客按项目找到可执行的使用说明。首页保持简洁，只列项目入口；文章以准备条件、操作步骤、结果验证和常见问题为主，不做按时间排序的博客流。

首批覆盖 README 中的四个项目：电影场次监控与自动锁座、应用商店、领克签到助手、蓝牙调试助手。每个项目先提供一篇入门教程。后两个项目属于独立仓库，写作时以其当前 README 和发布说明核对安装、权限及操作步骤；无法从当前资料确认的细节只链接上游说明，不编造流程。

本次只实现站点与教程内容，不部署生产环境，不引入评论、账号、CMS、标签、搜索或文章时间线。

## 页面与内容

- `/guide/`：站点标题、简短说明和四个项目的单列入口；顶部提供返回工具箱首页的链接。
- 每篇教程：标题、适用场景、准备条件、分步操作、如何验证成功、常见问题与相关链接。使用 VitePress 默认的文章目录和移动端导航，少量样式调整即可，不重建主题组件。
- 猫眼教程：以访问密钥、城市/影院/影片关注、测试推送和监控状态为主；自动锁座作为可选章节，清楚区分会话准备、规则保存和实际下单，不要求读者在教程中执行真实订单。
- 应用商店教程：浏览资源、预览和下载，并说明无需登录的访问方式。
- 领克和蓝牙教程：分别覆盖上游项目确认过的最短可用流程；示例不包含会话、令牌、推送密钥或其他真实凭据。

项目入口和正文里的站内链接均指向 `/guide/`；打开真实工具或外部仓库时使用明确的外链。工具箱现有首页添加一个教程入口，但不改现有四个工具的业务页面。

## 构建与集成

教程 Markdown、VitePress 配置和轻量样式放在 `worker/guide/`，VitePress 作为 `worker` 的开发依赖，沿用现有 `npm --prefix worker ci`。站点以 `/guide/` 为 base，构建结果由 `worker/scripts/build-assets.mjs` 纳入其受控临时目录，最终只发布到 `worker/public/guide/`；不复制源码、`node_modules` 或本地文档。

生产与示例 Wrangler 配置都增加 `/guide` 和 `/guide/*` 域名路由。Worker 静态资源处理负责裸路径跳转、教程 HTML、生成的脚本和样式以及不存在页面的 404；缓存与 CSP 需让 VitePress 页面正常加载，并不放宽现有猫眼、商店的策略。现有 API 与调度逻辑不变。

`pages/index.html` 是工具箱首页源码，但不在当前 Worker 静态资源白名单中；修改它只能保证仓库源码有入口，不能推断根站点已随 Worker 部署更新。上线时须另行确认根站点发布路径。

## 验证与边界

- 安装锁定依赖后，VitePress 构建和现有 Worker 静态资源构建可重复运行；产物包含首页、四篇教程和所需脚本/样式。
- 检查 `/guide` 跳转、`/guide/` 和各文章链接、未知路径 404，以及四个项目到工具或上游仓库的链接；构建产物不得包含忽略的本地资料或密钥。
- 运行现有 Worker 单测，并补充静态资源、路由和链接测试；在桌面与手机视口检查导航、正文、代码块和长链接无溢出。
- 教程内容只以当前代码和上游资料为依据；实际运行效果、外部应用权限以及生产域名可达性仍需发布时单独核对。
