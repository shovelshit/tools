# Maoyan Local Lock And Security Fixes

## Scope

Add a local Python command-line tool that uses Chromium only for an interactive
login. All later cinema, seat, and order requests use HTTP. The tool stops at
an unpaid order confirmation and never invokes payment APIs.

The existing Worker and Pages application will also receive the previously
identified security and correctness fixes. Existing KV data does not need to be
migrated.

## Local Lock Tool

`maoyan_lock.py login` opens a dedicated Playwright Chromium profile. The user
finishes SMS or risk-control verification. The command captures the browser
session, including cookies, CSRF data, and a H5Guard signature generated by a
harmless same-origin request, then closes Chromium.

`maoyan_lock.py lock` reads the owner-only local session file and performs the
following over HTTP: fetch cinema shows, resolve a target `seqNo`, fetch its
seat page, choose two contiguous selectable seats nearest the screen centre,
and POST `/ajax/createOrder`. It reports the unpaid order result without
calling payment endpoints. Authentication, risk-control, or signature failures
are surfaced as a request to run `login` again; no browser fallback is used.

Session data stays local in an ignored file with mode `0600`. It is never
committed, sent to KV, logged, or included in error messages.

## Worker And Pages Security Changes

- Replace FNV-derived user namespaces with random token IDs. Token metadata
  contains an ID, token, remark, and creation time only.
- Remove last-used writes and the admin "in use/recent use" model. The admin
  list derives "monitoring" or "stopped" from each token's stored config and
  expiry state.
- Revoke tokens through a JSON POST body carrying the token ID, rather than a
  DELETE URL query. Token values are returned only when created and otherwise
  masked in the admin list.
- Return notification-secret presence flags from `GET /api/config`, never Bark
  or ServerChan credentials. Empty values in a config update keep existing
  credentials.
- Restrict CORS methods to actual supported methods and remove the obsolete
  DELETE dependency.
- Preserve the show date when flattening show data, and use China local dates
  for Maoyan day parameters.
- Do not advance a movie snapshot when notification delivery fails, so the
  next scheduled run can retry it.
- Escape all AList-controlled text and URL attributes before inserting HTML,
  sanitize rendered Markdown, and remove public CORS-proxy fallbacks.
- Proxy AList HTTP files with manual redirects, validating every redirect host
  and protocol before following it.
- Add bounded fetches and response validation for Maoyan upstream requests.

## Validation

No automated test files will be added at the user's request. Verification is
performed with Python syntax checks, Worker module syntax checks, static scans
for secret echoes and unsafe Store rendering paths, and a non-payment CLI dry
run. A real lock request is not part of verification because it changes the
user's ticket inventory.
